# 구독과 크레딧

Onttle은 **월 구독 플랜 + 크레딧** 과금 방식을 사용합니다. Workspace마다 플랜을 구독하면 매 결제 주기에 플랜의 월간 크레딧이 지급되고, 서비스 사용량이 지표로 집계된 뒤 지표별 단가에 따라 크레딧이 차감됩니다.

이 문서를 읽고 나면 결제 주기가 언제 갱신되는지, 크레딧이 어떻게 차감되고 소진되면 무엇이 일어나는지, 플랜 변경·해지·결제 실패가 어떻게 처리되는지 알 수 있습니다.

> 구독 모델 도입 전에 사용하던 **선불 크레딧 충전**은 더 이상 제공되지 않습니다. 자동 충전은 추가 크레딧을 자동으로 구매하는 방식으로 제공됩니다([자동 충전](#자동-충전)). 기존 Workspace가 어떻게 전환되었는지는 [기존 Workspace의 전환](#기존-workspace의-전환)을 참고하세요.

## 플랜과 월간 크레딧

플랜은 Workspace 단위로 구독하며, 매월 결제됩니다. 플랜마다 다음이 정해져 있습니다.

| 항목        | 내용                                                                          |
| ----------- | ----------------------------------------------------------------------------- |
| 월 요금     | 결제일마다 기본 카드로 자동 결제됩니다. Free 플랜은 결제되지 않습니다.         |
| 월간 크레딧 | 결제 주기가 시작될 때 지급되는 크레딧입니다. 무제한 플랜은 크레딧 한도가 없습니다. |
| 플랜 한도   | 멤버 수, 프로젝트 수, 프로젝트당 테이블 수, 파일 업로드 크기, 저장 용량 등     |
| 기능 제공   | 요청 로그, 버전 기록, 커스텀 도메인·테마 제공 여부와 지원 등급                      |

요금은 모두 **부가세(10%) 포함** 금액입니다. 플랜별 요금과 월간 크레딧, 한도는 [요금제와 한도](/docs/usage-and-billing/plans-and-limits)와 [`/pricing`](/pricing) 페이지, 대시보드의 **Workspace → 결제** 메뉴에서 확인할 수 있습니다.

Workspace를 새로 만들 때 플랜을 선택합니다. 유료 플랜을 선택하면 생성 과정에서 카드를 등록하고 첫 달 요금이 즉시 결제되며, Free 플랜은 결제 수단 없이 시작할 수 있습니다.

> **무제한 플랜 (Enterprise 등)**: 사용량은 리포트를 위해 계속 측정되지만 크레딧은 차감되지 않으며, 크레딧 부족으로 요청이 거절되지 않습니다. 추가 크레딧도 구매할 수 없습니다.

## 결제 주기

| 항목          | 내용                                                                                             |
| ------------- | ------------------------------------------------------------------------------------------------ |
| 결제일        | 구독을 시작한 날짜가 매월의 결제일이 됩니다. 29~31일에 시작했다면 **28일**로 고정됩니다.          |
| 결제 시각     | 매 결제일 **오전 9시 (KST)**                                                                     |
| 주기 범위     | 이번 결제 시각부터 다음 결제 시각 직전까지                                                       |
| 갱신 시 처리  | 유료 플랜 요금 결제 → 새 주기 시작 → 플랜의 월간 크레딧 지급                                     |

새 주기가 시작되면 Workspace 잔액은 플랜의 월간 크레딧으로 **다시 설정**됩니다. 이전 주기에 남아 있던 크레딧(추가 크레딧 포함)은 이월되지 않고 소멸합니다.

결제가 완료되면 Workspace 소유자와 관리자에게 결제 금액, 결제 기간, 지급된 크레딧이 담긴 확인 메일이 발송됩니다.

## 차감 흐름

```
서비스 사용
    ↓
사용량 지표 기록 (DATA_STORE_BYTES, API_READ_CALLS 등)
    ↓
지표별 단가 계산 (단위 기준 올림 × 단위당 크레딧)
    ↓
Workspace 크레딧 잔액에서 차감
```

- 크레딧 차감은 **Workspace 단위**로 이루어집니다. 여러 Project가 있어도 잔액은 하나의 Workspace에서 공유됩니다.
- 사용량은 지표의 단위 크기로 올림한 뒤 단위당 크레딧을 곱해 계산합니다.
- 크레딧을 사용하는 요청은 실행 전에 잔액을 먼저 확인합니다. 잔액이 부족하면 요청이 실행되지 않습니다. Webhook도 발송 전에 잔액을 확인하며, 부족하면 발송을 건너뜁니다.
- 사용량은 작업이 끝난 뒤 기록되므로, 긴 AI 응답처럼 실제 사용량이 확인 시점의 예상보다 크면 잔액이 **0 아래로** 내려갈 수 있습니다. 이 차감은 취소되지 않습니다.
- 잔액이 음수인 동안에는 크레딧을 사용하는 작업이 모두 거절됩니다. 다음 결제일의 월간 크레딧 지급이나 추가 크레딧 구매로 음수 잔액이 먼저 상쇄되고, 남은 금액을 사용할 수 있습니다.
- 무제한 플랜(Enterprise 등)은 사용량만 측정하고 크레딧을 차감하지 않습니다.

어떤 지표가 차감에 영향을 미치는지는 [지표 종류](/docs/usage-and-billing/metric-types)를, 지표별 단가와 월 비용 시뮬레이션은 [`/pricing`](/pricing) 페이지를 참고하세요.

## 크레딧이 소진되면

잔액이 요청에 필요한 크레딧보다 적으면 다음과 같이 처리됩니다.

| 항목         | 내용                                                                                                   |
| ------------ | ------------------------------------------------------------------------------------------------------ |
| 요청 처리    | `insufficientCredit` (HTTP 400) 오류로 거절됩니다. 데이터와 설정은 그대로 유지됩니다.                  |
| 알림         | Workspace 소유자와 관리자에게 크레딧 부족 메일이 발송됩니다. 같은 Workspace에는 하루 최대 한 번 발송됩니다. |
| 자동 충전    | [자동 충전](#자동-충전)을 켜 두었다면 요청을 거절하기 전에 기본 카드로 추가 크레딧을 먼저 구매합니다. 꺼져 있거나 결제에 실패하면 잔액은 채워지지 않습니다. |
| 다시 사용하려면 | 다음 결제 주기를 기다리거나, 추가 크레딧을 구매하거나, 자동 충전을 켜거나, 플랜을 업그레이드합니다. |

```json
{
  "title": "Insufficient Credit",
  "message": "이번 결제 주기의 워크스페이스 크레딧이 부족합니다. 다음 주기에 크레딧이 갱신되며, 추가 크레딧을 구매하거나 플랜을 업그레이드할 수 있습니다."
}
```

## 추가 크레딧 (Add-on)

이번 주기의 크레딧이 모자랄 때 추가 크레딧을 구매할 수 있습니다.

- **Workspace → 결제** 메뉴에서 구매합니다. 소유자 또는 관리자 권한이 필요하며, 기본 결제 수단이 등록되어 있어야 합니다.
- 1,000 / 3,000 / 5,000 / 10,000 / 30,000 크레딧 중에서 고르거나 직접 수량을 입력합니다. 한 번에 최대 100,000 크레딧까지 구매할 수 있습니다.
- 기본 카드로 **즉시 결제**되고 잔액에 바로 더해집니다. 구매 완료 메일이 발송됩니다.
- 추가 크레딧은 **현재 결제 주기에만** 유효합니다. 주기가 끝나면 남은 추가 크레딧도 함께 소멸합니다.
- 무제한 플랜에서는 구매할 수 없습니다 (`addonNotAvailable`).

추가 크레딧의 가격은 월간 크레딧과 같습니다.

| 결제 통화 | 환산             |
| --------- | ---------------- |
| KRW       | 1 KRW = 1 Credit |

현재는 KRW 결제만 지원하며, 결제 금액은 부가세(10%)가 포함된 금액입니다.

## 자동 충전

자동 충전을 켜 두면 잔액이 기준보다 낮아졌을 때 추가 크레딧을 기본 카드로 자동 구매해, 크레딧 부족으로 사용이 중단되지 않도록 합니다.

**Workspace → 결제** 메뉴의 **자동 충전**에서 설정합니다. 소유자 또는 관리자 권한이 필요하며, 결제 수단이 등록되어 있어야 켤 수 있습니다.

| 설정             | 내용                                                                                           |
| ---------------- | ---------------------------------------------------------------------------------------------- |
| 잔여 크레딧 기준 | 잔액이 이 값보다 낮아지면 자동 충전이 시작됩니다.                                              |
| 충전 크레딧      | 한 번 충전할 때 구매하는 크레딧입니다.                                                         |
| 월 한도 (선택)   | 한 달(매월 1일~말일, KST) 동안 자동으로 구매할 최대 크레딧입니다. 비워두면 제한이 없습니다.    |

- 크레딧을 사용하는 요청이 들어올 때 잔액을 확인합니다. 잔액이 기준보다 낮거나 요청에 필요한 크레딧보다 적으면 기본 카드로 결제하고, 충전된 크레딧을 잔액에 더한 뒤 요청을 처리합니다. 충전 완료 메일이 발송됩니다.
- 가격과 유효 기간은 추가 크레딧과 같습니다. 자동 충전된 크레딧도 **현재 결제 주기에만** 유효하며, 주기가 끝나면 함께 소멸합니다.
- 월 한도에 도달하면 다음 달이 될 때까지 자동 충전이 멈춥니다.
- 결제가 실패하면 같은 카드로는 6시간 동안 다시 시도하지 않습니다. 기본 결제 수단을 바꾸면 바로 다시 시도합니다. 그동안 잔액이 부족한 요청은 `insufficientCredit` 오류로 거절됩니다.
- Enterprise 플랜과 무제한 플랜에서는 동작하지 않으며, 구독 결제가 연체된 동안에도 멈춥니다.

## 2026년 12월 1일부터

2026년 12월 1일 00:00 (KST)부터 AI 토큰과 저장 용량의 크레딧 계산 방식이 바뀝니다. 그 전까지는 현재 단가가 그대로 적용됩니다.

| 항목                                              | 현재                                                 | 2026년 12월 1일부터                                                                                |
| ------------------------------------------------- | ---------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| AI 토큰 (`AI_GENERATION_TOKENS`, `AI_ASK_TOKENS`) | 전체 토큰 100만 개당 500 크레딧                      | 입력 ×1, 캐시된 입력 ×0.1, 캐시 쓰기 ×1.25, 출력(추론 포함) ×5로 가중한 토큰 100만 개당 700 크레딧 |
| 데이터 저장                                       | 저장할 때 1 GB당 1,000 크레딧 (늘어난 용량만, 한 번) | 저장되어 있는 용량 기준 GB·월당 800 크레딧을 매일 차감 (`DATA_STORE_GB_DAYS`)                      |
| 파일 저장                                         | 업로드할 때 10 GB당 1,000 크레딧 (한 번)             | 저장되어 있는 용량 기준 GB·월당 200 크레딧을 매일 차감 (`FILE_STORAGE_GB_DAYS`)                    |

- 저장 요금은 그날 저장되어 있는 바이트 × 일수를 기준으로 매일 자동 차감됩니다. `DATA_STORE_BYTES`와 `FILE_UPLOAD_BYTES`는 통계용으로 계속 기록되지만 크레딧은 차감되지 않습니다.
- 가중치별 단가 등 자세한 내용은 [지표 종류](/docs/usage-and-billing/metric-types#2026년-12월-1일부터)를 참고하세요.

## 플랜 변경

| 변경 종류    | 적용 시점      | 결제                                                                                                    |
| ------------ | -------------- | ------------------------------------------------------------------------------------------------------- |
| 업그레이드   | 즉시           | 현재 주기의 남은 기간에 대한 요금 차액을 일할 계산해 기본 카드로 결제합니다. 같은 비율의 월간 크레딧 차액도 즉시 지급됩니다. |
| 다운그레이드 | 다음 결제일    | 결제 없음. 다음 결제일까지 현재 플랜과 크레딧을 그대로 사용합니다.                                       |
| 해지         | 다음 결제일    | 결제 없음. 현재 주기가 끝나면 Free 플랜으로 전환됩니다. 데이터는 삭제되지 않습니다.                     |

- 예약된 다운그레이드나 해지는 적용 전까지 **Workspace → 결제** 메뉴에서 취소할 수 있습니다. 취소하면 현재 플랜이 평소처럼 갱신됩니다.
- 이미 Free 플랜인 Workspace는 해지할 수 없습니다 (`nothingToCancel`).
- 결제가 연체된 상태에서는 플랜을 변경할 수 없습니다 (`subscriptionPastDue`). 결제 수단을 먼저 정리해야 합니다.

## 결제 수단

- **Workspace → 결제** 메뉴에서 카드를 등록합니다. 결제는 KG이니시스(포트원)를 통해 진행되며, 카드를 한 번 등록하면 이후 정기 결제·업그레이드·추가 크레딧 구매·자동 충전이 이 카드로 결제됩니다.
- Workspace당 최대 **3개**의 카드를 등록하고, 그중 하나를 기본 결제 수단으로 지정할 수 있습니다.
- 결제 수단 관리는 소유자 또는 관리자만 할 수 있습니다.

---

## 결제 실패와 연체

정기 결제가 실패하면 다음 순서로 처리됩니다.

1. 구독이 **연체(PAST_DUE)** 상태가 되고 소유자와 관리자에게 결제 실패 메일이 발송됩니다.
2. 원래 결제일로부터 **1일 후**, 그리고 **3일 후**에 같은 청구서로 결제를 다시 시도합니다.
3. 재시도에 성공하면 새 주기가 시작되고 월간 크레딧이 지급됩니다.
4. 모든 재시도가 실패하면 Workspace는 새 주기부터 **Free 플랜**으로 전환되며 메일로 안내됩니다.

연체 상태에서는 플랜을 변경할 수 없으므로, 카드를 교체하거나 기본 결제 수단을 바꾼 뒤 재시도를 기다리세요.

## 인보이스와 결제 내역

- **Workspace → 인보이스** 메뉴에서 월 정기 결제, 업그레이드 차액, 추가 크레딧 구매, 자동 충전 등 모든 결제의 인보이스를 확인합니다. 소유자와 관리자만 볼 수 있습니다.
- 인보이스 상세에서 결제 항목, 결제 수단, 결제 상태와 영수증 링크를 확인할 수 있습니다.
- **다음 결제 예정** 화면에서 다음 결제일, 적용될 플랜, 결제 예정 금액을 미리 볼 수 있습니다.
- **Workspace → 결제** 메뉴에서는 현재 주기의 포함 크레딧·추가 크레딧·사용량·남은 잔액과 크레딧 지급 내역을, **Workspace → 사용량** 메뉴에서는 지표별·프로젝트별 사용량을 확인할 수 있습니다.

## 기존 Workspace의 전환

구독 모델 도입 전에 만든 Workspace는 처음 결제 관련 기능을 사용할 때 자동으로 전환됩니다.

- **Free 플랜**에 배정되고 Free 플랜의 월간 크레딧을 받습니다.
- 이전 방식에서 구매해 둔 크레딧 잔액은 첫 결제 주기의 **추가 크레딧**으로 유지됩니다. 첫 주기가 끝나면 다른 추가 크레딧과 마찬가지로 소멸합니다.
- 크레딧이 더 필요하면 유료 플랜으로 업그레이드하거나 추가 크레딧을 구매하세요. 자동 충전을 사용하려면 **Workspace → 결제** 메뉴에서 설정을 확인하세요([자동 충전](#자동-충전)).

## 자주 발생하는 오류

| 오류 코드                       | 상태 | 원인과 해결 방법                                                              |
| ------------------------------- | ---- | ----------------------------------------------------------------------------- |
| `insufficientCredit`            | 400  | 이번 주기 크레딧 부족. 추가 크레딧 구매, 플랜 업그레이드 또는 다음 주기 대기 |
| `paymentMethodRequired`         | 422  | 기본 결제 수단 없음. 카드를 등록한 뒤 다시 시도                               |
| `paymentFailed`                 | 402  | 카드 결제 실패. 결제 수단 확인 후 다시 시도                                   |
| `subscriptionPastDue`           | 409  | 정기 결제 연체 중. 결제 수단을 정리한 뒤 플랜 변경                            |
| `addonNotAvailable`             | 400  | 무제한 플랜에서는 추가 크레딧을 구매할 수 없음                                |
| `nothingToCancel`               | 400  | 이미 Free 플랜                                                                |
| `planProjectLimitReached` 등    | 403  | 플랜 한도 도달. 리소스를 정리하거나 플랜 업그레이드                           |
| `planFileSizeLimitExceeded` 등  | 413  | 파일 크기 또는 저장 용량이 플랜 한도 초과                                     |
