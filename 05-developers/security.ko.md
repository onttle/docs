# 보안

**Workspace → 보안**은 Workspace의 보안 기능을 모아 둔 메뉴입니다. 만료되었거나 오래 쓰이지 않은 **API 키 상태**를 한눈에 보여 주고, Pro+ 이상에서는 **IP 허용·차단 목록**과 **허용 이메일 도메인**으로 접근을 제한합니다. 같은 메뉴의 [Audit 로그](/docs/developers/audit-log)는 보안에 영향을 주는 변경을 누가, 언제, 어디서 했는지 기록합니다.

이 문서를 읽고 나면 주의가 필요한 API 키를 찾고, API 요청과 멤버 초대를 제한하는 방법을 알 수 있습니다.

---

## 누가 볼 수 있나요

보안 메뉴는 Workspace **소유자**(OWNER)와 **관리자**(ADMIN)만 사용할 수 있습니다. 편집자와 게스트에게는 사이드바에서 비활성화되어 표시되고, API로 직접 요청해도 거부됩니다.

---

## API 키 상태

보안 메뉴 상단에는 워크스페이스의 **모든 프로젝트**에서 주의가 필요한 API 키가 모여 표시됩니다. 플랜과 관계없이 제공됩니다.

| 상태 | 조건 |
| ---- | ---- |
| 만료됨 | 만료일이 지나 요청이 거부되는 키 |
| N일 후 만료 | 7일 안에 만료되는 키 |
| N일 미사용 | 활성화되어 있지만 90일 이상 사용되지 않은 키 |

**키 관리**를 누르면 해당 프로젝트의 API Keys 페이지로 이동해 만료일을 연장하거나 키를 삭제·비활성화할 수 있습니다. 만료일 설정 방법은 [REST API 인증](/docs/rest-api/authentication)을 참고하세요.

---

## IP 허용·차단 목록

**Pro+ 이상**에서 이 워크스페이스의 API 키로 들어오는 요청을 클라이언트 IP로 제한합니다. 대시보드 접속에는 적용되지 않습니다.

| 목록 | 동작 |
| ---- | ---- |
| 차단 목록 (blacklist) | 목록의 IP에서 온 요청을 항상 거부합니다. 허용 목록보다 먼저 적용됩니다. |
| 허용 목록 (whitelist) | 비어 있지 않으면 목록의 IP에서 온 요청만 허용하고 나머지는 모두 거부합니다. |

- 한 줄에 하나씩 IPv4·IPv6 주소 또는 CIDR 범위(`203.0.113.9`, `10.0.0.0/8`, `2001:db8::/32`)를 입력합니다. 목록당 최대 100개입니다.
- 거부된 요청은 `403 ipNotAllowed`를 받습니다. 저장한 목록은 1분 안에 API에 적용됩니다.
- 허용 목록을 쓸 때는 서버, CI, 협력사의 고정 IP를 모두 넣었는지 확인하세요. IP를 확인할 수 없는 요청도 거부됩니다.
- 플랜을 Pro 이하로 내리면 목록은 보존되지만 적용되지 않고, 다시 올리면 그대로 적용됩니다.

---

## 허용 이메일 도메인

**Pro+ 이상**에서 목록에 있는 도메인의 이메일만 이 워크스페이스에 초대할 수 있습니다. 회사 계정만 참여하게 하려는 팀에 유용합니다.

- 한 줄에 하나씩 도메인(`example.com`)을 입력합니다. 정확히 일치하는 도메인만 허용되며 하위 도메인은 따로 적어야 합니다. 최대 50개입니다.
- 목록에 없는 도메인을 초대하면 `emailDomainNotAllowed` 오류로 초대가 거부됩니다. 여러 명을 한 번에 초대할 때는 한 명이라도 걸리면 전체가 거부됩니다.
- 이미 참여한 멤버와 대기 중인 초대에는 영향이 없습니다.

두 정책의 변경은 모두 Audit 로그에 `보안 정책` 분류로 기록됩니다.
